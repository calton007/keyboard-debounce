# KeyboardDebounce Design

## 目标

KeyboardDebounce 是一个 Windows 用户态键盘防抖托盘程序，用低层键盘钩子缓解机械或笔记本键盘的异常短间隔重复触发。

## 防抖策略

- 运行态按 `虚拟键码 + 扫描码 + Extended 标志` 维护独立时间线，避免主键区和扩展键互相干扰；持久化学习状态和配置键列表仍按虚拟键码保存，兼容已有数据。
- 同一键在有效阈值内再次 `KeyDown` 时拦截；窗口以最近一次观察到的 `KeyDown` 为准，持续抖动不会按放行时间周期漏出。
- 过滤器维护下游实际收到的按键状态：未交付的 `KeyDown` 所对应的 `KeyUp` 也拦截；这项待配对状态会跨暂停和忽略切换保留。若旁路期间先出现新的物理 `KeyDown`，则视为已经交付，最终 `KeyUp` 正常放行。
- 明显长按超过 `LongHoldBypassMs` 后放行，避免破坏退格、方向键和普通长按输入。
- 全局敏感度只影响运行时有效阈值，基础阈值仍按键保存。
- `Ctrl`、`Shift`、`Alt`、`Win` 等修饰键，以及带 `LLKHF_INJECTED` 标记的软件注入输入，始终直通且不参与学习。
- 暂停和启动延迟期间在进入引擎前旁路；恢复时只清运行态，不清学习状态。

## 游戏 EXE 自动切换

- 只按用户明确添加的 EXE 文件名启用，不分析窗口标题、安装目录或程序类型，也不自动识别游戏。
- 设置页提供“浏览选择 EXE”和“从正在运行的程序添加”两个批量入口，不要求手工输入。选择文件不会执行或解析 EXE。
- 配置继续保存规范化后、不带 `.exe` 的文件名并忽略大小写去重，保持旧 `GameProcesses` JSON 字段兼容；路径不同但文件名相同的 EXE 视为同一项。
- 托盘上下文每秒在钩子回调之外获取一次运行中 EXE 快照；手动刷新进入同一个串行检测 gate，不另设 UI 轮询器。检测器一次枚举返回全部已配置且正在运行的 EXE，首个命中项仍按配置顺序作为活动 EXE。配置变更发生在检测期间时合并排队一次重跑；过期结果丢弃。
- `GameModeRuntimeSnapshot` 是游戏模式单一真源，原子保存实际模式、无 `.exe` 后缀的活动项、完整运行集合、逐行未知集合、检测健康状态和原始错误。活动项、集合、健康状态或错误任一变化都会递增 UI 运行态版本；当前页事件驱动刷新，预热后的隐藏页在下次激活时补刷。
- 完整检测成功会替换模式和逐行状态并清除旧错误。部分进程不可读时仅确认已命中的行，其余显示“状态未知”；整体失败时保留上一次实际模式和逐行状态。两种失败都会显示原始错误，并在后续成功后恢复。关闭自动切换、清空名单或移除当前命中项会立即退出游戏模式，不按检测失败处理。
- 游戏模式只对 `GameModeFilteredKeys` 中的键执行防抖；列表为空时所有普通键直通。修饰键、注入输入和始终忽略键仍按原旁路规则处理。
- 游戏阈值取普通有效阈值和 `GameModeThresholdMs` 的较小值，长按使用独立的 `GameModeLongHoldBypassMs`。
- 游戏模式完全冻结学习状态、计数、最近事件和阈值调整；模式切换只重置运行态，避免跨模式时间线误判。

## 自学习

- 已放行事件永不提高阈值。只有普通模式下、已经发生物理 `KeyUp`、且拦截间隔位于有效阈值最后 `5ms` 内的事件可作为上调证据；长按重复不参与。
- 连续两次符合条件后，基础阈值调整为 `ceil((间隔 + 5ms) / GlobalSensitivity)`，上限为 `min(250ms, DefaultThresholdMs + 40ms)`；相同节奏达到目标后不继续增长。
- 任意放行、长按、非贴边拦截或模式切换都会清空上调证据。
- 仅当基础阈值高于默认值，且连续 12 次放行间隔达到 `max(300ms, 2 × 有效阈值)` 时下降 `5ms`，最低只回到默认阈值。
- 最近调整量、原因和时间写入学习状态，便于诊断学习是否发生。
- 稳定衰减由近期连续稳定事件决定，不依赖终身累计的拦截计数。
- 学习状态版本 2 首次加载旧数据时，仅将高于当前默认值的基础阈值重置到默认值，保留较低阈值和累计统计；写回前创建一次性 `learning-state.pre-v2.json`，失败时保留内存修复值并沿用原子保存和指数退避重试。

## 忽略键

- 忽略列表按虚拟键码保存。
- 忽略键完全放行，不参与拦截、不创建学习状态、不更新统计。
- 表格仍显示已忽略键，方便取消忽略。

## 设置界面架构

- `SettingsWindow` 只负责 WinUI 3 外壳、事件驱动刷新和页面导航；业务控件分别位于概览、普通防抖、游戏模式、按键管理、应用设置五页。窗口创建时预热五页，后续切换复用同一实例。游戏检测由托盘每秒执行，界面不创建第二个轮询器。
- `SettingsUiContext` 共享权威的设置、学习状态、引擎、存储路径和保存委托；页面不得复制业务状态。除暂停热键由“应用热键”显式提交外，现有设置继续即时保存。
- 顶部始终提供全局启用/暂停开关；最近事件集中在概览页，保存失败或状态读取失败时才在其他页面显示错误条。自动刷新只更新外壳和当前页动态值，不重建页面或打断输入；隐藏页切回时恢复缓存集合和焦点。
- 顶部导航支持鼠标、方向键和 `Alt+1` 至 `Alt+5`；设置窗口每次新建默认进入概览，窗口存续期间保留页面内搜索、筛选、排序、选中行和编辑焦点。
- 界面固定使用 WinUI 3 的 Scheme 3 浅色基准，不提供深色主题切换；标题栏保持系统原生样式，交互控件继续使用 WinUI 3 的键盘焦点和自动化语义。
- 按微软的 [桌面应用调用 WinRT API 指南](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/winrt-apis-desktop-apps)，应用目标为 `net8.0-windows10.0.19041.0`，并启用 Per-Monitor V2 DPI；主题与系统事件订阅必须随窗体释放。
- 游戏模式页采用等宽双栏控制中心：左侧投影托盘上下文提供的权威模式快照及同步滑块/数值框，右侧显示 EXE 添加入口、逐行运行状态和移除操作。页面不枚举进程；逐行状态原地更新，不重建列表或抢走焦点。手动刷新仅请求托盘重新检测，读取失败时持续显示原始错误，直到一次成功读取。
- 固定宽编辑器同时声明逻辑宽度和 `MinimumSize.Width`，避免隐藏页面在首次 Per-Monitor V2 缩放前被临时窄布局压缩后无法恢复。

## 按键管理

- 启动时默认打开设置窗口；用户勾选“静默运行”后，下次启动只进入托盘。
- 搜索同时匹配十进制 VK 和按键名，150ms 防抖且不写配置；范围包含全部、仅已学习、仅游戏防抖和仅始终忽略。
- `VK` 排序时所有行按 VK 正常排序。
- `阈值(ms)` 显示按全局敏感度换算后的实际运行阈值；基础学习阈值仍保存在学习状态中。
- 非 `VK` 排序时未忽略项始终在前，忽略项始终在后，升序和降序都不反转这个分组规则。
- 自动刷新只原地更新已有行数值，不改变搜索、筛选、排序、选择或当前焦点。
- 列表视口跟随页面剩余高度扩展：默认窗口至少展示约 5 条完整按键，最小窗口至少展示 3 条，超出时使用列表自身滚动而不是裁切隐藏。
- 新按键出现后需要手动刷新才会加入表格。
- 游戏 EXE 可从磁盘或当前运行列表批量添加并直接移除；首次添加会开启自动切换，当前匹配 EXE 及模式状态会周期刷新。
- “游戏防抖”列只决定游戏模式下仍需过滤的故障键；“始终忽略”列在所有模式下优先直通。
- 启动延迟和暂停热键可在界面修改。热键重绑失败时保留旧绑定；若启动时注册失败，之后启用防抖会再次尝试注册。

## 隐私和边界

- 用户配置保存到 `%APPDATA%\KeyboardDebounce\settings.json`。
- 自动学习状态保存到 `%APPDATA%\KeyboardDebounce\learning-state.json`。
- 设置文件保存功能参数、规范化后的 EXE 文件名和虚拟键列表，不保存 EXE 路径；学习文件保存按键阈值、计数、时间和学习原因。两者都不保存输入文本或文本序列。
- 配置写入使用同目录临时文件和原子替换，并保留 `.bak`；损坏内容复制到 `.corrupt-*` 隔离文件后再恢复。设置无法恢复时保持停用，学习数据无法恢复时重置为空。
- 普通学习统计按 5 秒窗口合并为后台检查点，阈值调整立即保存；保存失败按 1 秒起步、最高 60 秒的指数退避自动重试，错误在成功恢复前持续可见。
- 程序是用户态方案，不覆盖登录界面、UAC 安全桌面或所有管理员权限窗口。
- 低层钩子不能稳定区分内置键盘和外接键盘，因此忽略规则对所有键盘全局生效。
- 每个用户会话只运行一个实例；默认暂停热键为 `Ctrl+Alt+F11`，注册失败时不允许启用防抖。
- 开机自启状态不仅检查注册表值是否存在，还要求命令实际指向当前可执行文件；写入失败会恢复界面和配置中的原状态。
